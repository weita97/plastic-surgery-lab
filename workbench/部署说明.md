## 为什么正式版和开发版数据不会串

GitHub Pages 的所有项目站都挂在 `weita97.github.io` 这**一个域名**下，而浏览器的 localStorage 按**域名**隔离、**不看路径**。如果两版共用存储键名，开发版一打开就会读写正式版的数据。

所以存储前缀在**构建时注入**：源码里 `core.js` 写的是占位符 `__WB_PREFIX__`，`build.js` 按参数替换成 `wb1_`（正式）或 `wb1d_`（开发）。两套键名不同，同一个浏览器里可以并存互不影响。

打开开发版时顶部有橙色提示条「🧪 开发版 · 数据独立存储（wb1d_）」；万一前缀注入失败会变成红条警告，`node tools/check.js --dev` 也会直接报错退出。

## 一键部署

改完源码后，在工作台目录执行：

```powershell
cd "C:\Users\廖伟权\Desktop\每日学习工作台\workbench"

# 部署正式版 → workbench/
powershell -ExecutionPolicy Bypass -File tools\deploy.ps1 "改了什么"

# 部署开发版 → workbench-dev/
powershell -ExecutionPolicy Bypass -File tools\deploy.ps1 "改了什么" -Dev
```

脚本会依次做 5 件事：

1. `node build.js`（开发版自动加 `--dev`）—— 把 `src/` 下的 CSS、数据、模块内联成单文件，并注入对应存储前缀
2. `node check.js` —— 抽出所有 `<script>` 逐个 `node --check`，再校验前缀是否注入正确，有问题就中止
3. 同步仓库对应目录（正式版额外同步一份到桌面 `每日学习工作台.html`）
4. `git add / commit / push` 到 GitHub（SSH 密钥在 `_ssh\id_ed25519`）
5. 轮询线上地址，直到字节数与本地一致（最多 120 秒），确认真的生效

提交说明不传就自动用「更新每日学习工作台 + 版本 + 时间」。

> ⚠️ 推送到 stderr 的 git 进度信息会让 PowerShell 显示红色 `NativeCommandError`，这是正常的，只要看到 `已推送 commit xxx` 就成功了。

## 注意事项

- **云端同步**：见下节。未登录时数据只在本机浏览器；登录后自动加密同步。
- **实时抓取需联网**：顶刊速递每天打开时向 PubMed 拉近三年文献，并用在线翻译补中文。断网时自动回退到内置的 199 篇文献库。
- **GitHub Pages 有构建延迟**：push 后通常 30–90 秒生效，deploy.ps1 会自动等到生效为止。
- **换行符**：仓库已设 `core.autocrlf false`，保证线上字节与本地一致。若在别的机器上克隆，记得也设一下。

## 云端同步（GitHub Gist 后端）

### 原理

- **登录**：用你自己的 GitHub 个人访问令牌（PAT）验证身份，只需 `gist` 权限。
- **存储**：数据加密后写进你账号下的**一个私有 Gist**（`wb-data.json`），只有你能看到。新设备登录时会**自动找到账号下已有的那个 Gist 并复用**，不会各建各的。
- **加密**：AES-GCM 256 位，密钥由令牌经 PBKDF2（12 万次迭代）派生。换错令牌解不开，Gist 泄露也是密文。
- **合并**：**三方比对**（本机 / 云端 / 上次同步时的基线快照）。逐键判断谁动过：只有本机动过就取本机、只有云端动过就取云端、两边都没动就保持；**云端删了就真删，本机删了也真删**。数组（账本、日程、收藏、单词）再逐条比对，两端各自新增的记录都能保住，只有同一条记录两端都改过时才按修改时间取较新的一份。
- **多 Gist 兜底**：若历史上因旧版本 Bug 产生过多个同步 Gist，登录时会自动**全部读取并合并**，界面会显示「云端存储：N 个同步 Gist」。

### 第一次使用

1. 打开 https://github.com/settings/tokens/new?scopes=gist
2. Note 随便填（如 `workbench`），Expiration 选 **No expiration**，Scopes **只勾 gist**
3. 点最下方 Generate token，复制 `ghp_` 开头那串
4. 打开工作台 → 左侧「☁️ 云端同步」→ 粘贴 → 点「🔑 登录并同步」

### 手机端

同一个网址 `https://weita97.github.io/plastic-surgery-lab/workbench/` → 「云端同步」→ 粘贴**同一个令牌** → 登录，数据自动拉下来。

> 若手机端已有旧数据、想以电脑端为准：点「⬇ 只下载（从云端拉取）」，只拉不推。

### 排查

模块页面上会显示「🔍 云端存储：N 个同步 Gist · 最近更新 xxx」。

- 正常应为 **1 个**。若显示 2 个以上，说明历史版本曾在不同设备各建过一个，现在会自动合并，无需手动处理。
- 若显示「无法读取云端状态」，说明令牌失效或网络不通。

### 同步规则：打开拉一次，改动自动传

| 动作 | 时机 | 说明 |
|---|---|---|
| ⬇ **拉取** | **每次打开工作台都自动跑一次** | 登录时也算一次。会做三方比对，把另一台设备的改动（含删除）如实拉下来 |
| 📤 **上传** | 任何改动 **4 秒后自动同步** | 记账、**删账**、写复盘、收藏/取消收藏、标记已学、改日程，全自动，可关闭 |
| ⬇ 手动拉取 | 随时 | 点「⬇ 只下载（从云端拉取）」，只拉不推 |

**同步走三方比对，不是并集**：拿本机、云端、上次同步时的基线三份对比，逐键判断谁动过。
所以你在账本里删掉 5 笔，另一台设备打开后那 5 笔会真的消失；日历删某天安排、取消收藏选题、取消「已学」标记，同理都会真实同步删除。

**多端冲突**：同一条记录两端都改过时，**以最后改动的那一端为准**。但两端**各自新增**的不同记录会全部保留，不会互相覆盖。

> 也就是说：电脑和手机都是「打开就拉最新、改动 4 秒后传云端」，两端始终能对上。

### 令牌失效怎么办

- 令牌删了/过期了：重新生成一个，进「云端同步」→ 退出登录 → 重新粘贴。
- **不要**把令牌发给任何人，它等同于账号密码。若怀疑泄露，去 GitHub 删掉重新生成。

### 实现文件

- `src/js/cloud.js` —— 后端逻辑（登录、加密、Gist 读写、三方比对合并、自动同步钩子）
  - `merge3()` / `merge3Value()` —— 键级三方比对：`lEqB` 取云端（删除即删除）、`rEqB` 取本机、都不等则比 `lts/rts`
  - `merge3Array()` —— 数组逐条三方比对，用每条自己的 `ts` 判断谁更新
  - `push()` —— 本机为准整份上传（手动「立即上传」走这条）
  - `sync()` —— 自动同步主路径：云端空则上传；与云端一致返回 `'same'`；否则三方比对 → 应用 → 与云端仍不同再回传
  - `pull()` —— 只下载，三方比对但只写本机不回传
  - `bootSync()` —— 打开工作台时调用，直接 `sync()`（**不能先 push**，否则会抹掉另一台设备刚上传的数据）
  - `snapshot()` / `applySnapshot()` —— 读写 localStorage 全量快照；合并结果里已不存在的键会被 `removeItem`
  - `ensureKts()` / `mergeKts()` —— 键级最后改动时间（`wb1_cloud_kts`），冲突时用来判断谁更新
- `src/js/mod_cloud.js` —— 界面（登录页、同步面板、使用说明）
- 存储键：`wb1_cloud_token` / `wb1_cloud_user` / `wb1_cloud_gist` / `wb1_cloud_last` / `wb1_cloud_mode` / `wb1_cloud_dev` / `wb1_cloud_base`（基线快照）/ `wb1_cloud_base_at` / `wb1_cloud_kts`
- 测试：`tools/test_sync.js`（34 项单元测试，含跨端删除、整键删除、两端各自新增、同一条冲突）、`tools/probe_open_sync.js`（浏览器级 17 项）
